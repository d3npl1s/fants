# Desktop-версия «Фантов» — заметки Агента C

Ветка: `feature/desktop-ui` (поверх `bbe51b6`, v1.6).
Файлы этапа: **только** `css/desktop.css` и этот документ. `index.html`, `css/style.css`,
`js/app.js`, `sw.js` и данные не менялись — подключение делает интегратор (инструкция ниже).

## Что это такое

Один продукт, одна логика, тот же мобильный дизайн. `desktop.css` — чистый слой
override'ов, **каждое правило живёт внутри media query**; ниже 768px файл не делает
ничего (проверено на 390×844 — вид идентичен v1.6).

## Брейкпоинты

| Диапазон | Что происходит |
|---|---|
| < 768px | без изменений (файл молчит) |
| 768–1023px (планшет/мал. ноутбук) | центральная колонка для форм (~660px), шире подписи карточек, чипы пакетов по центру; модалки остаются bottom sheet |
| ≥ 1024px (desktop) | основной слой: игроки 2×N, настройки DM сеткой 2 колонки, список проверок DM 2 колонки, модалки центрированные окна, тонкие скроллбары, hover-фидбек |
| ≥ 1440px | чуть больше воздуха: крупнее главный экран, шире колонки (720–1080px), ничего не разъезжается по краям |
| ≥ 1024px и высота ≤ 760px | guard для ноутбуков 720p: компактнее заголовки/кнопки/формы, чтобы «Начать», «Дальше», вердикты DM попадали в первый экран |

Ширина viewport — единственный критерий (не `pointer: fine`): ноутбуки с тачскрином
получают тот же layout, а тапы остаются кликами. Hover-стили, напротив, спрятаны в
`@media (hover: hover) and (pointer: fine)` — на тач-устройствах sticky-hover нет.

## Ключевые решения по экранам

- **Главный**: полноразмерный градиент остаётся, контент центрируется, крупнее
  корона/заголовок на ≥1024 и ≥1440. Версия — внизу, как было.
- **Игроки**: список `grid-template-columns: 1fr 1fr` от 1024px (≥900px по факту
  комфортно, но порог держан на «desktop»-границе ТЗ), контейнер ≤1080px. Поле
  имени не сжимается: чипы пола/удаления фиксированной ширины из базового CSS.
- **Выбор игры / уровней**: карусель **осталась слайдами на всю ширину** — синхронизация
  точек и листание в `app.js` считают шаг = `clientWidth` карусели
  (`syncGames`, `syncCarousel`, `scrollBy`), поэтому «карточки рядом» чистым CSS
  ломают навигацию (подробнее — «Ограничения»). Внутри слайда контент собран в
  компактную колонку: иконка/название/подпись/кнопка центрируются
  (`justify-content: center`), подписи ≤460–520px, кнопка ≤340–360px.
  Чипы пакетов ограничены 1160/1240px и центрируются.
- **Колесо**: фон-полосы на весь экран, кнопка спина 172px (не раздувается),
  HUD и подпись по центру; на 720p кнопка 150px и всё в первом экране.
  Явный click по большой кнопке уже был («Смахни или нажми!») — жест не обязателен.
- **Правда/действие**: карточки в 2 колонки (это было с ≥700px), от 1024px кластер
  центрируется по вертикали (`justify-content: center`), карточки ≤900/980px,
  текст 19px. Секретные задания продолжают скрывать содержание в превью
  (базовая логика не тронута — проверено на скриншотах: «Секретное действие»).
- **Задание**: текст ≤680px (фразы ≤740px) — строка ≈55–75 символов. Нижняя панель
  остаётся полосой на всю ширину, но её содержимое центрируется: замечание о
  наказании ≤820px, кнопки «Выполнено/Не выполнено» ≤680px, широкие кнопки ≤520px,
  панель оценки ≤620px. Секретный режим (скрытый TTS, «Прочитать задание») без
  изменений.
- **Продолжи фразу**: настройки и итоги — колонка ≤680/720px; чипы режимов в один
  ряд 4×1 от 1024px (`#modeChips`); круг — пара по центру высоты (`margin: auto 0`),
  слоты 230px, «Фраза!» ≤420px; на 720p форма настройки целиком в первый экран.
- **Нарисуй по памяти**: настройки — grid 2 колонки ≤1040px (заголовок, подзаголовок,
  предупреждение, итог «игроки × слова = всего слов/проверок» и кнопка — во всю
  ширину сетки, итог визуально выделен как был); слушание/дорисовка — крупный номер
  150px по центру, слово не показывается (логика та же); список проверок — 2 колонки
  ≤1000/1080px, строка счёта выровнена по ширине карточек; проверка — номера 6×N
  ≤640px, вердикты в ряд из трёх, раскрытие ≤560px — на 720p всё в первом экране.
- **Модалки**: от 1024px — центрированные окна `width: min(560px, 92vw)`,
  `max-height: min(86dvh, 760px)`, скругление со всех сторон, тонкий скроллбар.
  Статистика — 2 колонки карточек игроков. На планшете/телефоне bottom sheet
  сохранён (скриншот `768x1024-03`).
- **Hover** — только дополнительная подсветка/сдвиг на 1–3px, без обязательных
  анимаций; всё управляется кликом/фокусом. `:focus-visible` из `style.css`
  не отключался. `prefers-reduced-motion` гасит добавленные переходы.
- **Клик-зоны**: базовые размеры ≥44px сохранены; точки карусели уже имели
  невидимые 44px-зоны (`::before` в style.css) — не тронуты.

## Найдено и починено при проверке

1. Системный скроллбар модалки настроек — грубая белая полоса поверх скруглённой
   карточки → тонкий стилизованный скроллбар для всех скролл-контейнеров desktop
   (`.modal-card`, формы, списки DM).
2. На 720p вердикты DM-проверки уходили за первый экран → сетка номеров 6 колонок
   и компактный guard-слой.
3. Блок «правда/действие» и кластер пары висели вверху на 1080p → вертикальное
   центрирование.
4. Форма «Продолжи фразу» на 720p не вмещала «Начать» → уплотнённый guard
   (отступы, чипы 4×1, кнопки 60px).

## Инструкции интегратору

1. Принять ветки B и A (по протоколу в `00-agent-dispatch.md`), затем ветку
   `feature/desktop-ui`.
2. В `index.html` **после** строки
   `<link rel="stylesheet" href="css/style.css?v=1.6">`
   добавить:
   ```html
   <link rel="stylesheet" href="css/desktop.css">
   ```
   Порядок важен: desktop-правила должны побеждать по каскаду. Параметр `?v=`
   для `desktop.css` не обязателен (файл не кешируется SW, см. п. 3), но при
   желании можно добавить `?v=1.6` для единообразия — при смене версии не забыть
   поднять её в будущем релизе вместе с остальными.
3. В `sw.js` добавить `'css/desktop.css'` в массив `CORE` (precache), чтобы
   desktop-стили работали офлайн. Файл без `?v=` — SW-обработчик версионных
   ассетов его не трогает, сеть/кеш отработают штатно.
4. Поднять `CACHE`-имя и `?v=` ссылок + `main-ver` одним коммитом (обычный
   релизный чеклист проекта) — это делает интегратор, не этап C.
5. Тесты после интеграции: мобильный прогон 320/360/390 (вид не должен измениться),
   затем 768×1024, 1024×768, 1280×720, 1366×768, 1920×1080 — по списку экранов ниже.

(номера+вердикты)/итоги DM. Ключевые экраны также на 1920×1080, 1366×768,
1024×768, 768×1024 и мобильная санити-проверка 390×844 (players + wheel).

Чек-лист ТЗ, пройденный вручную в браузере: горизонтального скролла страницы нет;
вертикальный скролл не обрезает кнопки (формы докручиваются, главное — в первом
экране на 720p); модалки в экране; длинные имена не ломают строки игроков

`:focus-visible` сохранена); колонки не разъезжаются на 1440+.

## Ограничения и что можно сделать на следующем этапе (требует JS)

- **Карточки игр «рядом»**: показать все три карточки одновременно без правок
  `app.js` нельзя — синхронизация точек/свайпов считает шаг карусели равным её
  ширине. Если захочется настоящий 3-up layout: карточке дать `min-width: 33.33%`,
  а в `syncGames`/`syncCarousel`/стрелках заменить `clientWidth` на ширину карточки
  (или шаг = `car-track.children[0].offsetWidth`). Это единственное место, где
  desktop-цель ТЗ не достигнута чистым CSS.
- **Точки карусели**: невидимые 44px-зоны перекрываются между соседями (расширение
  `::before` больше шага точек) — клик мышью ровно по центру точки может попасть
  в зону соседа. Лечится уменьшением `inset` у `.dots .dot::before` до `-10px`
  при ≥1024px в рамках правки `style.css` (вне зоны этапа C, не менял).
- **Выделение текста**: `body { user-select: none }` мешает копировать текст
  задания на ПК. Разрешение выделения только внутри `.reveal-text` — правка
  `style.css`, вне зоны этапа.
- Hot/Soft уровни и блиц отдельно не перекрашивались — палитры наследуются через
  `--c1/--c2` и работают как на мобильном.
